MikroTik hEX S — FTTH Italia

> Configurare un router MikroTik (RouterOS 7) su fibra FTTH italiana con PPPoE su VLAN 802.1Q

RouterOS 7 PPPoE VLAN 802.1Q hEX S / hAP / RB5009
← PROGETTI
Nota. Guida generica: gli indirizzi usano la LAN di default del MikroTik (192.168.88.0/24) e IP/credenziali reali non sono riportati. Gli esempi usano il nome simbolico <UTENTE_ISP> / <PASSWORD_ISP>. La parte finale (pubblicazione di servizi su internet / port-forwarding) è volutamente omessa.

0 — Come funziona la fibra italiana

L'operatore porta in casa un ONT (ONU/terminatore ottico) che espone una porta Ethernet. Quasi tutti gli operatori italiani incapsulano la sessione in una VLAN 802.1Q e autenticano con PPPoE (RFC 2516). Il router del cliente deve quindi:

1) creare una VLAN sulla porta verso l'ONT → 2) avviare un client PPPoE su quella VLAN → 3) applicare NAT in uscita → 4) distribuire la LAN con DHCP/DNS → 5) proteggere il router con un firewall di base.

Attenzione. L'ID VLAN dipende dall'operatore (ed a volte dall'area). Se il PPPoE non sale, il primo sospetto è la VLAN sbagliata o l'MTU.

Requisiti

• Un router MikroTik con almeno 2 interfacce (es. hEX S, hAP, RB5009).
• La porta ether1 collegata all'ONT dell'operatore.
• Le credenziali PPPoE fornite dall'ISP (utente/password).
• Accesso RouterOS (Winbox / WebFig / SSH).

Modelli con SFP: se il tuo operatore fornisce un modulo GPON SFP/SC, puoi inserirlo nel cage sfp1 invece di usare un ONT esterno. In tal caso sostituisci ether1 con sfp1 nei comandi seguenti.

Fase 1 — VLAN di accesso (802.1Q)

Si crea la VLAN sull'interfaccia collegata all'ONT. L'MTU si abbassa a 1492 (80 byte di overhead PPPoE).

# esempio con VLAN 835 (TIM/Tiscali/WindTre)
/interface vlan
add interface=ether1 name=vlan-isp vlan-id=835 mtu=1492

Fase 2 — Client PPPoE

Il client PPPoE gira sopra la VLAN, diventa la rotta di default e prende il DNS dal peer.

/interface pppoe-client
add name=pppoe-isp interface=vlan-isp \
    user="<UTENTE_ISP>" password="<PASSWORD_ISP>" \
    add-default-route=yes use-peer-dns=yes disabled=no
Verifica: /interface pppoe-client monitor pppoe-isp deve mostrare status: connected con un IP pubblico assegnato.

Fase 3 — LAN: bridge, IP, DHCP, DNS

Si raggruppano le porte LAN in un bridge, si assegna l'indirizzo del gateway e si attiva il server DHCP.

# bridge LAN (ether2..ether5)
/interface bridge
add name=lan
/interface bridge port
add bridge=lan interface=ether2
add bridge=lan interface=ether3
add bridge=lan interface=ether4
add bridge=lan interface=ether5

# gateway della LAN
/ip address
add address=192.168.88.1/24 interface=lan

# pool + server DHCP
/ip pool
add name=dhcp-lan ranges=192.168.88.10-192.168.88.200
/ip dhcp-server
add name=dhcp1 interface=lan address-pool=dhcp-lan
/ip dhcp-server network
add address=192.168.88.0/24 gateway=192.168.88.1 dns-server=192.168.88.1

# DNS resolver (con inoltro a server pubblici)
/ip dns
set allow-remote-requests=yes servers=1.1.1.1,8.8.8.8

Fase 4 — NAT (source NAT in uscita)

Una sola regola di masquerade sull'interfaccia PPPoE abilita la navigazione a tutta la LAN.

/ip firewall nat
add chain=srcnat out-interface=pppoe-isp action=masquerade

Fase 5 — Firewall di base

Regole minime: accettare connessioni già stabilite, consentire la gestione solo dalla LAN, bloccare tutto il resto in ingresso dal WAN e proteggere il forward con lo stateful tracking. 

# -- input (verso il router) --
/ip firewall filter
add chain=input action=accept connection-state=established,related
add chain=input action=accept in-interface=lan
add chain=input action=drop

# -- forward (tra LAN e WAN) --
add chain=forward action=accept connection-state=established,related
add chain=forward action=drop connection-state=invalid
add chain=forward action=accept in-interface=lan
add chain=forward action=drop
Hardening servizi. Disabilita i servizi inutili e limita la gestione alla LAN: /ip service disable ftp,telnet,www,www-ssl e /ip service set ssh,winbox address=192.168.88.0/24.

Fase 6 — Verifica rapida

/interface pppoe-client monitor pppoe-isp once
/ip route print where dst-address=0.0.0.0/0
/ping 1.1.1.1 count=4
/tool dns-resolve name=example.com

Sempre valido: i valori sono indicativi e possono cambiare nel tempo o per area. Fonti autorevoli sono la pagina “parametri di connessione” dell'operatore o l'etichetta del modem fornito.

Troubleshooting

SintomoCausa probabileRimedio
PPPoE non sale (connecting…) VLAN errata o credenziali sbagliate Verifica vlan-id con l'ISP e ricontrolla utente/password
Connessione sale ma siti lenti/bloccati MTU PPPoE Imposta mtu=1492 sulla VLAN e mss clamp in forward
No internet in LAN NAT o DHCP assenti Controlla la regola masquerade e il server DHCP
DNS non risolve Resolver disattivato allow-remote-requests=yes e dns-server nel DHCP network

Parte finale

Da qui in avanti si tratterebbe di pubblicare servizi su internet (port-forwarding / reverse proxy / certificati): una configurazione specifica e sensibile che — per buona pratica di sicurezza — non viene pubblicata in questa guida. Il router così configurato naviga su internet e resta protetto, senza esporre nulla verso l'esterno.
